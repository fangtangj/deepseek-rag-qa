# 课程简介

## 一、课程名称与定位

**课程名称**：Java 后端开发核心技术与实战

**课程定位**：面向已掌握 Java 基础语法（变量、流程控制、面向对象、集合框架）的学习者，目标是补齐从"能写 Java"到"能写生产级后端服务"之间的能力缺口。课程不讲语法细节，只讲后端开发中真正会用到、面试会问、线上会踩坑的核心技术。

**课程性质**：项目驱动型课程。全程围绕一个「在线课堂」实战项目展开，每一讲的知识点都会落到项目的某个功能模块上。

## 二、适合人群与前置要求

### 适合人群

1. 计算机相关专业在校生，准备 Java 后端开发实习或校招。
2. 会写 Java 但没做过后端项目，不清楚 Spring Boot 工程结构的人。
3. 参加过培训班、会用框架但不理解原理、面试一问底层就卡住的人。

### 前置要求

- 掌握 Java SE 基础：集合（List、Map）、异常、泛型、IO。
- 了解 HTTP 协议基本概念：请求方法、状态码、请求头。
- 听说过 Maven，知道它是用来管理依赖的。
- 不要求会 Spring，课程从零讲起。

## 三、课程大纲（共 8 讲）

| 讲次 | 主题 | 对应项目模块 |
|---|---|---|
| 第 1 讲 | 并发编程基础与 Java 线程池 | 课程资料异步批处理 |
| 第 2 讲 | Spring Boot 自动装配与启动流程 | 项目脚手架搭建 |
| 第 3 讲 | MySQL 索引原理与 SQL 优化 | 课程、订单表查询优化 |
| 第 4 讲 | Redis 缓存设计与三大缓存问题 | 课程详情页缓存 |
| 第 5 讲 | 分布式锁与并发控制 | 选课防超卖 |
| 第 6 讲 | 消息队列与异步解耦 | 作业提交通知 |
| 第 7 讲 | 接口设计与统一异常处理 | 课程答疑接口 |
| 第 8 讲 | 项目部署与性能压测 | 上线前收尾 |

## 四、学习路径与建议

### 推荐学习顺序

按讲次顺序学习，不要跳讲。原因：第 1 讲的线程池知识会在第 5 讲的分布式锁中复用，第 3 讲的索引知识是第 8 讲性能压测的基础，知识点之间存在明确的前置依赖。

### 每讲的学习方法（三步法）

1. **看讲义**：先通读本讲讲义 Markdown，理解概念和原理。
2. **跟敲代码**：把讲义里的代码示例在本地跑一遍，不要只看不写。
3. **做课后作业**：每讲末尾配有 1 道课后作业，要求独立完成。

### 时间安排建议

- 每讲建议投入 4–6 小时（含看讲义、敲代码、做作业）。
- 全职学习建议每天 1 讲，一周内完成全部 8 讲。
- 在职或在校学习建议每周 2 讲，四周内完成。

## 五、课时与考核方式

### 课时安排

- 总课时：32 学时。
- 每讲 4 学时（讲义 2 学时 + 实操 2 学时）。
- 第 1、3、5 讲为重点讲次，建议额外增加 2 学时练习。

### 考核方式

课程采用「作业 + 期末项目」双轨考核：

| 考核项 | 占比 | 说明 |
|---|---|---|
| 课后作业 | 40% | 每讲 1 次，共 8 次，全部必须提交 |
| 期末项目 | 60% | 独立完成一个后端服务，需提交代码与接口文档 |

### 作业提交规则（重要）

- 每讲作业在该讲结束后的**第 7 天 23:59** 前提交。
- 提交方式：项目仓库提交 Pull Request，或按助教指定的目录上传。
- 逾期提交：每逾期 1 天扣该次作业成绩的 10%，逾期超过 3 天按 0 分计。
- 作业可以讨论思路，但代码必须自己写。发现抄袭，当次作业记 0 分。

### 期末项目要求

1. 使用 Spring Boot 搭建一个至少包含 5 个 REST 接口的服务。
2. 使用 MySQL 存储数据，至少设计 3 张表并建立合理索引。
3. 使用 Redis 做缓存或分布式锁，并说明使用场景。
4. 提交 README，写清楚接口列表、启动方式和关键技术选型理由。

## 六、课程配套资源

- **讲义**：每讲一份 Markdown 讲义，存放在课程资料的 `docs/` 目录下。
- **代码仓库**：每讲的示例代码单独一个分支，按 `lesson-1`、`lesson-2` 命名。
- **课程答疑**：课程配套一个基于课程资料的 AI 答疑接口，可以对讲义内容提问，回答会附上出处文件名。
- **常见问题**：学习过程中遇到的共性问题统一记录在《常见问题 FAQ》中，提问前请先查阅。

## 七、学习目标（学完能达到什么水平）

完成本课程后，你应当能够：

1. 独立搭建一个 Spring Boot 后端项目，理解工程目录结构与依赖管理。
2. 说清楚线程池、索引、缓存、分布式锁这四类高频考点的底层原理，而不只是会调 API。
3. 面对一条慢 SQL，能看懂执行计划并给出优化方案。
4. 面对一个并发场景，能判断该用本地锁还是分布式锁，并说出选型理由。
5. 把课程内容整理成简历里的项目经历，并应对面试官对项目细节的追问。

## 八、常见误区提醒

1. **误区一：只看不写。** 后端技术是实践技能，看讲义产生的"我懂了"的感觉是假的，必须动手。
2. **误区二：追求框架数量，忽视底层。** 会用十个框架但说不清一个的原理，面试不会加分。
3. **误区三：跳过基础直接学微服务。** 线程池、索引、缓存这些基础没打牢，学微服务只是背名词。
4. **误区四：作业抄网上的代码。** 作业的意义是暴露你没掌握的地方，抄了等于白学。
